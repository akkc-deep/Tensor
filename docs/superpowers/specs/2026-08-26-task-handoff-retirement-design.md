# Tensor 旧任务交接流程退役设计

> **历史记录（已被取代，2026-08-31）：** 本文关于保留 `docs/planning/task-index.md` 的决定已被项目所有者正式取代；正文仅用于说明 2026-08-26 的迁移，不再定义当前任务工作流。当前唯一权威任务索引为 [`docs/task-handoffs/tensor-v1-task-board.md`](../../task-handoffs/tensor-v1-task-board.md)。

## 状态

- 方案边界已由项目所有者于 2026-08-26 确认。
- 本次只迁移普通项目文档，不初始化 `.task-handoff`，也不准备、授权或启动任何任务。
- 当前目录不是 Git 仓库，因此不能依赖提交历史恢复删除内容；实施前需生成一份明确限定范围的临时恢复归档。

## 目标与非目标

目标是移除 Tensor 项目内重复维护的通用任务交接规则，让任务交接生命周期、权限、状态、审计、归档和恢复统一由用户级 `managing-task-handoffs` Skill 管理，同时保留 Tensor 独有的任务、依赖、工时、模块计划、设计要求和验收内容。

本次不初始化任务交接，不选择候选任务，不改变任何任务的启动状态，不修改产品 BRD、PRD、TRD，也不改动生产源码。

## 方案比较

### 方案 A：删除全部交接目录

优点是清理彻底；缺点是会一并删除 77 个项目任务及其依赖、工时等独有资产，并留下大量失效引用。不可采用。

### 方案 B：保留现状

优点是没有迁移成本；缺点是项目文档和 Skill 会继续形成两套状态、授权、归档和恢复规则。不可采用。

### 方案 C：定向迁移

删除旧的手工当前状态和归档规则，移动并保留项目任务索引，精简任务设计规范，改写路线图和模块计划中的旧入口及手工生命周期规则。该方案保留项目知识，同时让通用交接治理只有一个来源，因此采用本方案。

## 文件处理

### 删除

- `docs/task-handoffs/task-handoff.md`：旧的手工当前状态、读取授权、门禁和生命周期载体。
- `docs/task-handoffs/records/README.md`：旧的手工记录命名与归档规则。
- 删除文件后若 `docs/task-handoffs/records/` 和 `docs/task-handoffs/` 为空，不保留空目录。

### 移动并保留

- 将 `docs/task-handoffs/task-index.md` 移至 `docs/planning/task-index.md`。
- 保留其中 15 个模块、77 个任务、206 AI 小时、交付物和依赖关系。
- 删除索引中“执行者先读旧交接文档”“旧交接白名单授权”等通用流程说明；索引只承担 Tensor 项目计划职责。

### 精简并保留

- `docs/task-designs/README.md` 继续规定 Tensor 任务设计文档的路径和项目所需内容。
- 删除其中对旧交接文件、旧记录目录和手工状态流转的依赖。
- 任务设计文档是项目输入资产，不承担运行时授权或当前状态职责。

### 改写引用方

- 更新总路线图、路线图设计规范和 15 个模块计划中的旧路径、旧入口、精确读取白名单、手工状态流转及旧归档说明。
- 各模块保留项目特有的候选输入、文件边界、依赖、步骤和验收；候选输入不表示任务已经启动或自动获得额外权限。
- 将 `M00-T04` 从“建立单一交接文档及治理规则”改为“建立 Tensor 任务设计与验收证据模板”，保持任务总数、工时和后续依赖不变，避免未来重新创建已退役流程。
- 项目文档不复制 Skill 的通用生命周期、授权矩阵、审计、恢复或存储规则。

## 数据与职责边界
