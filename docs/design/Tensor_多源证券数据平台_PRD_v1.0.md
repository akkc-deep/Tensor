## 1. 产品概述

### 1.1 背景

内部证券数据获取目前缺少统一入口。不同数据源的认证方式、参数和返回结构各不相同，若直接在业务流程中调用具体数据源，会导致扩展成本高、数据结构混杂，也不便于确认数据是否已经成功入库。

Tensor 首期提供一个最小可用的证券数据工具：以插件方式接入 Tushare Pro，支持手动下载 49 类数据，按来源接口适配并写入独立数据表，再通过页面筛选和查看已入库数据。

### 1.2 产品目标

1. 为内部用户提供统一、可理解的数据下载入口。
2. 完成 Tushare Pro 49 类数据的端到端下载、适配和持久化。
3. 让用户能够确认下载结果，并分页查看数据库中的真实记录。
4. 通过插件、适配器和来源独立表，验证后续新增数据源时无需修改核心产品流程。

### 1.3 成功标准

首期发布必须同时达到以下标准：

| 维度 | 成功标准 |
|---|---|
| 接口覆盖 | Tushare Pro 49 个接口全部可选，覆盖率为 49/49 |
| 端到端闭环 | 每个接口都能完成参数填写、请求、结果反馈；有效非空样例可完成入库和查看 |
| 字段完整性 | 每张表覆盖对应 `docs/data-template/<api_name>.json` 的全部 `fields` |
| 数据正确性 | 页面查询结果与数据库记录一致 |
| 幂等性 | 相同业务唯一键重复下载后不产生重复记录 |
| 扩展性 | 测试插件可在不修改核心下载、持久化和查看流程的情况下注册、调用和停用 |
| 可启动使用 | 用户按项目说明完成必要配置后，可以启动完整服务、打开页面并使用首期全部功能 |

### 1.4 产品原则

- **来源隔离**：不同数据源、不同接口的数据不混表。
- **配置驱动**：页面参数、字段和筛选能力来自插件及适配配置，不在页面硬编码 Tushare Pro 规则。
- **结果明确**：成功、成功但无数据、失败必须是三个可区分的结果。
- **写入可靠**：适配或持久化失败时不允许留下部分数据。
- **首期从简**：只实现手动下载和只读查看，不扩展为调度、治理或插件市场平台。

### 1.5 全局完成标准

本期所有功能统一采用“可启动、可操作、可完成”的用户验收标准。一个功能只有同时满足以下条件，才视为完成：

1. 用户按照项目提供的启动说明完成必要配置并启动前端、后端及所需基础服务。
2. 用户能够在支持的浏览器中打开产品页面，无需修改源代码或通过开发工具补充操作。
3. 用户能够从页面入口完成该功能的完整操作，并看到本 PRD 定义的最终结果。
4. 页面操作产生的接口、数据库和错误处理结果与本 PRD 一致。
5. 启动与使用步骤已经形成可执行说明，新环境可按说明复现。

单元测试、接口测试、数据库检查和代码完成只能作为辅助证据，不能单独作为功能完成结论。除准备 Token、数据库连接等运行配置及构造异常验收数据外，不得依赖直接调用接口、手工执行 SQL 或修改数据库来替代页面操作。

## 2. 用户与使用场景

### 2.1 目标用户

首期按单一受信内部用户设计。用户具备基本的证券数据概念，知道证券代码、交易日、公告日和 Tushare Pro 接口的含义。

首期不提供登录、用户管理、角色或数据权限控制，部署环境的访问控制由内部网络或部署设施承担。

### 2.2 核心任务

| 场景 | 用户目标 | 完成标志 |
|---|---|---|
| 下载交易日数据 | 选择日线等接口，指定交易日并下载 | 页面反馈实际返回和入库记录数 |
| 下载公告类数据 | 指定公告日，必要时填写证券代码 | 数据成功写入对应来源表 |
| 下载快照数据 | 按证券、交易所、月份或无参数下载 | 页面明确显示成功、空结果或失败 |
| 查询已入库数据 | 选择数据集，按证券代码和日期筛选 | 表格分页展示与条件匹配的数据 |
| 验证重复下载 | 使用相同参数再次下载 | 已有业务记录被更新，不产生重复行 |

## 3. 产品范围

### 3.1 首期包含

- 从插件注册表获取可用数据源及接口元数据。
- 提供完整服务的启动说明和必要配置说明。
- 读取 Tushare Pro Token 配置状态。
- 展示 Tushare Pro 的 49 个接口及其中文说明。
- 根据接口元数据动态展示和校验查询参数。
- 由用户手动发起单接口下载。
- 展示下载完成后的成功、成功但无数据或失败结果。
- 将来源结果交给对应适配器转换。
- 按 `plugin_id + api_name` 写入 49 张来源独立表。
- 按业务唯一键更新或插入数据。
- 选择数据源和数据集，按可用核心字段筛选。
- 展示总记录数、数据表格和分页控件。

### 3.2 首期不包含

- 登录、用户、角色和权限系统。
- Token 录入、展示、修改或多凭证管理页面。
- 定时任务、自动补数、批量接口下载、任务队列和自动重试。
- 下载状态机、执行阶段持久化和下载进度展示。
- 下载任务历史、运行看板、通知和告警中心。
- 数据编辑、删除、导出、图表分析和跨数据集查询。
- 原始响应归档、数据版本、血缘、质量评分和人工修复。
- 插件市场、插件在线安装、热加载和复杂插件管理。
- 多数据源字段统一、跨来源合并或主数据治理。
- 移动端专项适配。

### 3.3 前置条件与依赖

1. 运行环境已通过配置文件或环境变量提供有效的 Tushare Pro Token。
2. 运行环境能够访问 Tushare Pro API 和产品数据库。
3. Tushare Pro 账号具有目标接口所需积分或权限。
4. 49 个数据模板位于 `docs/data-template/`，并作为字段结构基线。
5. 每个适配器均已配置目标表、字段映射、类型转换、必填字段和业务唯一键。
6. 项目提供可执行的服务启动入口及说明，用户无需阅读实现代码即可完成启动。

### 3.4 需求优先级

| 优先级 | 定义 | 发布规则 |
|---|---|---|
| P0 | 完成首期业务闭环或保证数据正确性、安全性所必需 | 未通过时不得发布 |
| P1 | 影响操作效率和失败恢复体验的重要能力 | 应在首期交付；存在缺陷时须确认不阻断 P0 流程后再决定是否发布 |

## 4. 信息架构与通用交互

### 4.1 页面结构

首期仅提供两个一级页面：

1. **数据下载**：选择数据源与接口，填写参数并触发下载。
2. **数据查看**：选择数据源与数据集，筛选并分页查看已入库记录。

桌面端通过固定导航在两个页面间切换。首期不跨页面保留本次下载或查询结果。

### 4.2 查询与结果通用状态

数据源、接口、数据集加载以及数据查询区域必须覆盖以下状态。下载执行过程不展示阶段状态或进度，只在请求结束后展示最终结果。

| 状态 | 页面行为 |
|---|---|
| 初始 | 展示明确操作引导，不展示误导性的空表格 |
| 加载中 | 展示加载状态，禁用会产生重复请求的主操作 |
| 成功 | 展示返回内容与关键数量信息 |
| 空数据 | 展示空状态及当前查询条件，不视为错误 |
| 失败 | 展示可理解的错误摘要，并允许用户修正后重试 |

### 4.3 通用输入规则

- 日期控件按 `YYYY-MM-DD` 展示，提交时转换为 Tushare Pro 所需的 `YYYYMMDD`。
- 月份控件按 `YYYY-MM` 展示，提交时转换为 `YYYYMM`。
- 证券代码去除首尾空格，并按“代码.市场”格式校验，例如 `000001.SZ`。
- 枚举型参数使用单选下拉框，不允许自由输入未声明的值。
- 开始日期不得晚于结束日期。
- 校验错误显示在对应字段附近，并在修正前阻止提交。
- 页面不得显示、回填或通过错误信息泄露 Token。

## 5. 数据下载页面

### 5.1 页面目标

让用户完成“选择来源 → 选择接口 → 理解接口 → 填写参数 → 发起下载 → 确认结果”的完整操作。

### 5.2 页面组成

页面从上到下包含：

1. 数据源选择器；
2. 数据接口选择器；
3. 接口中文说明和查询方式；
4. 动态参数区域；
5. “开始下载”按钮；
6. 下载结果区域。

### 5.3 数据源选择

- 选项来自插件注册表，不在前端写死。
- 首期仅有 Tushare Pro 时默认选中该数据源，但仍展示数据源名称。
- 数据源不可用或配置缺失时展示不可用原因，并禁用接口选择与下载按钮。
- 页面只展示 Token 是否已配置，不展示 Token 内容。

### 5.4 接口选择

- 选择数据源后加载该插件声明的接口清单。
- 首期必须展示附录 A 中的全部 49 个接口。
- 每个选项至少包含接口名和中文说明。
- 49 个接口按八个业务分类分组，并支持按接口名或中文说明搜索。
- 切换接口时清空上一接口的参数值、校验错误和下载结果，防止参数误用。
- 未选择接口时不展示参数表单，“开始下载”按钮不可用。

### 5.5 动态参数

参数控件由插件声明的接口参数定义生成：

| 参数类型 | 页面控件 | 示例 |
|---|---|---|
| `trade_date`、`ann_date` | 单日期选择器 | 2026-08-07 |
| `start_date`、`end_date` | 日期范围控件 | 2026-08-01 至 2026-08-07 |
| `month` | 月份选择器 | 2026-08 |
| `ts_code` | 文本框 | 000001.SZ |
| `exchange`、`exchange_id` | 单选下拉框 | SSE、SZSE、BSE |
| `list_status` | 单选下拉框 | L、P、D |
| `hs_type` | 单选下拉框 | SH、SZ |
| 无参数 | 不展示输入控件 | `stk_managers` |

参数是否必填、枚举范围、默认值和说明以插件元数据为准。首期使用附录 A 给出的参数集合；页面不得通过硬编码判断某个具体 Tushare Pro 接口。

### 5.6 提交规则

用户点击“开始下载”后：

1. 页面先执行必填、格式和日期范围校验。
2. 校验通过后提交一次下载请求。
3. 请求执行期间禁用数据源、接口、参数和下载按钮，防止重复提交或结果错配。
4. 页面不展示“下载中”“适配中”“入库中”等阶段，也不展示进度条或百分比。
5. 后端按“下载 → 适配 → 事务入库”的线性流程执行，不采用状态机，不持久化执行阶段。
6. 首期不支持取消任务。请求结束后恢复页面操作；请求超时或失败时，用户可使用原参数重试。

### 5.7 结果反馈

| 结果 | 判定 | 页面反馈 | 数据库行为 |
|---|---|---|---|
| 成功且有数据 | 上游成功、适配成功、写入成功，`row_count > 0` | “下载成功”，显示上游返回数、插入数、更新数 | 按业务唯一键执行新增或更新 |
| 成功但无数据 | 上游成功，`row_count = 0` 且 `data = []` | “下载成功，0 条数据” | 不写入占位记录 |
| 失败 | 鉴权、权限、网络、上游、解析、适配或写入任一环节失败 | “下载失败”，显示错误摘要和处理建议 | 不得产生本次请求的部分写入 |

成功提示中的返回数必须来自本次上游响应；插入数和更新数来自本次数据库写入结果。首期不提供结果数据预览和历史记录。

## 6. 数据查看页面

### 6.1 页面目标

让用户选择一个已注册来源的数据集，以该数据集实际存在的核心字段进行筛选，并确认数据库中的记录。

### 6.2 页面组成

页面包含：

1. 数据源选择器；
2. 数据集选择器；
3. 动态筛选条件；
4. “查询”和“重置”按钮；
5. 查询结果总数；
6. 数据表格；
7. 分页控件。

### 6.3 数据集选择

- 数据源列表与下载页面来自同一个插件注册表。
- 选择数据源后，展示该来源声明且已完成持久化配置的数据集。
- 首期 Tushare Pro 必须包含全部 49 个数据集。
- 更换数据源或数据集时，清空旧筛选条件、查询结果和页码。
- 选择数据集后不自动查询；用户设置条件并点击“查询”。

### 6.4 动态筛选

筛选项根据目标表实际字段生成：

- 存在 `ts_code` 时展示证券代码精确筛选。
- 存在 `trade_date` 时展示交易日期范围筛选。
- 存在 `ann_date` 时展示公告日期范围筛选。
- 同时存在 `trade_date` 和 `ann_date` 时分别展示，且标注字段名称。
- 不存在对应字段时不展示该筛选项。
- 所有筛选项均可为空；无筛选条件时查询该数据集的全部记录并分页返回。
- 多个筛选条件之间使用“且”关系。
- “重置”清空筛选条件、查询结果和页码，但保留当前数据源和数据集。

### 6.5 表格展示

- 表头及顺序来自该数据集的适配配置，覆盖模板的全部业务字段。
- `source_plugin`、`source_api`、`ingested_at` 作为来源字段展示在业务字段之后。
- 不对超宽数据集裁剪字段；页面提供横向滚动。
- 存在 `ts_code` 时固定在表格左侧；不存在时固定第一个业务字段。
- 空值统一展示为 `--`，不得与数值 `0` 或空字符串混淆。
- 日期按 `YYYY-MM-DD` 展示；入库时间按当前系统时区展示到秒。
- 数值保留数据库中的有效精度，不在首期提供用户自定义格式。
- 单元格内容过长时截断显示，悬停可查看完整内容。
- 首期不支持前端排序、列配置、行选择、编辑、删除和导出。

### 6.6 分页

- 默认每页 50 条，可切换为 20、50 或 100 条。
- 展示符合当前筛选条件的总记录数、当前页和总页数。
- 切换筛选条件或每页条数后返回第 1 页。
- 翻页必须保留当前数据源、数据集和筛选条件。
- 最后一页删除或数据变化导致页码超出范围时，自动回到新的最后一页；首期页面本身不提供删除入口。

### 6.7 查询结果状态

| 状态 | 页面表现 |
|---|---|
| 未查询 | 提示用户选择数据集并设置查询条件 |
| 查询中 | 表格区域显示加载状态，禁用重复查询和分页操作 |
| 有数据 | 显示总数、表格和分页 |
| 无数据 | 显示“未找到符合条件的数据”，保留筛选条件以便修改 |
| 查询失败 | 显示错误摘要并提供“重新查询”入口，不展示旧结果为新结果 |

### 7.2 参数与下载

| 需求编号 | 优先级 | 需求描述 | 验收标准 |

| PRD-F-007 | P0 | 页面动态生成接口参数表单 | 49 个接口均展示与附录 A 一致的参数类型，不为单个接口写死页面 |

## 8. 数据与业务规则

### 8.1 表命名与字段

- 表名统一为 `<plugin_id>__<api_name>`。
- Tushare Pro 插件标识为 `tushare_pro`。
- 例如日线行情表为 `tushare_pro__daily`。
- 业务字段以对应 JSON 模板的 `fields` 为基线，字段顺序以适配配置为准。
- 每张表额外包含：
  - `source_plugin`：来源插件标识；
  - `source_api`：来源接口名；
  - `ingested_at`：本次成功入库时间。

### 8.2 业务唯一键

- 每个适配器必须显式声明其业务唯一键，不允许通过页面或运行时猜测。
- 唯一键应由能够稳定标识来源业务记录的字段组合构成。
- 数据库必须建立与业务唯一键一致的唯一约束。
- 首次出现的唯一键执行插入；已存在的唯一键更新全部可更新业务字段和 `ingested_at`。
- 业务唯一键字段缺失或为空时，本次适配失败，不执行写入。
- 具体字段组合属于各接口适配配置和数据库设计内容，发布前通过重复下载用例验证。

### 8.3 数据类型与空值

- 日期、数值、枚举和文本类型由适配配置明确声明。
- 来源空值转换为数据库空值，不得自动转换为 `0`、空字符串或当前日期。
- 数值转换不得因页面展示格式丢失原始有效精度。
- 适配后字段必须全部属于目标表定义；出现未声明字段时记录系统日志，但不扩展表结构。
- 模板新增、删除或重命名字段必须通过版本化变更更新适配配置和表结构，不在运行时自动改表。

### 8.4 一致性规则

- `fields`、`data`、适配字段和目标表字段在写入前完成一致性校验。
- `row_count` 必须与本次包络中的 `data` 行数一致；不一致时按解析失败处理。
- 页面成功结果仅在数据库事务提交后展示。
- `ingested_at` 以服务端时间生成，同一批次使用一致的时间基准。

## 9. 异常处理

| 异常类型 | 用户提示原则 | 系统处理 |
|---|---|---|
| Token 未配置 | 提示“数据源凭证未配置，请联系系统维护者” | 禁止发起下载，不返回敏感配置路径或内容 |
| Token 无效 | 提示“数据源鉴权失败，请检查凭证配置” | 本次失败，不重试、不写库 |
| 接口权限不足 | 提示“当前账号无该接口权限” | 本次失败，保留参数供用户重试 |
| 参数不合法 | 精确标出字段及正确格式 | 前端拦截；服务端仍进行同等校验 |
| 上游限流或服务错误 | 展示上游可理解摘要 | 本次失败，首期不自动重试 |
| 网络或超时 | 提示“请求超时或网络不可用，请稍后重试” | 中止本次处理，不写库 |
| 返回解析失败 | 提示“数据源返回格式异常” | 记录诊断日志，不写库 |
| 适配失败 | 提示失败接口和字段摘要 | 中止并记录日志，不写库 |
| 数据库失败 | 提示“数据入库失败，请稍后重试” | 回滚本次事务 |
| 查询失败 | 提示“数据查询失败”并提供重试 | 清除加载状态，不把旧数据标为新结果 |

用户提示应短而可行动；详细堆栈、SQL、Token 和内部路径仅允许进入受控系统日志，不得显示在页面。

## 10. 非功能需求

### 10.1 性能

- 在内部验收数据规模和正常网络条件下，数据查看接口返回 50 条记录的 P95 响应时间不超过 2 秒。
- 数据查询操作收到用户点击后 300 毫秒内必须出现加载反馈。
- 服务端查询必须使用分页，不允许一次把整张表加载到前端。
- `ts_code`、核心日期字段和业务唯一键应建立与查询及更新匹配的数据库索引。
- 下载性能受 Tushare Pro 响应影响，不设固定完成时长；单次请求达到服务端配置的超时时间后必须明确失败并释放资源。

### 10.2 可靠性

- 下载、适配和写入的边界清晰，任一失败均不影响既有已提交数据。
- 数据写入使用数据库事务，确保单次下载不会部分提交。
- 对相同唯一键的更新具有幂等性。
- 页面刷新或网络中断后不恢复本次下载请求和结果，但数据库唯一约束必须防止重复数据。

### 10.3 安全

- Token 仅通过配置文件或环境变量注入。
- Token 不进入前端响应、页面、普通日志、错误信息或数据库业务表。
- 系统日志对请求参数中的潜在敏感信息执行脱敏。
- 首期无应用内认证，产品必须部署在受控内网或由外部访问控制保护的环境中。

### 10.4 可维护性与扩展性

- 数据源接入遵守统一插件接口，适配遵守统一适配接口。
- 接口参数、数据集字段和筛选能力使用元数据驱动。
- 新增数据源时可以新增插件、适配器和来源表，不修改首期核心页面流程。
- 单个插件不可用时不得阻止其他插件完成注册和查询。

### 10.5 兼容性与可用性

- 首期以最新稳定版 Chrome 桌面浏览器为验收基准。
- 推荐视口宽度不小于 1280 像素；小于推荐宽度时页面可横向滚动，不丢失操作入口。
- 所有表单控件具有可见标签，错误不能只依赖颜色表达。
- 键盘可以完成选择、输入、提交、查询和分页的主要操作。

### 10.6 可观测性

- 每次下载和查询请求生成请求标识，用于关联服务端日志。
- 日志记录插件标识、接口名、参数摘要、返回数、插入数、更新数、耗时和最终结果类型。
- 失败日志记录失败阶段和可诊断原因，但不得记录 Token。
- 首期不提供面向用户的日志查询页面。

## 11. 埋点与产品度量

首期为内部工具，不建设独立分析平台。若已有统一埋点能力，应记录以下事件；若无，则以服务端结构化日志完成同等统计：

| 事件 | 关键属性 | 用途 |
|---|---|---|
| `download_submitted` | `plugin_id`、`api_name`、查询模式 | 统计接口使用覆盖 |
| `download_finished` | 最终结果类型、返回数、插入数、更新数、耗时、失败阶段 | 评估端到端成功率与主要失败原因 |
| `dataset_queried` | `plugin_id`、`api_name`、筛选项、结果数、耗时 | 评估数据查看使用情况和查询性能 |

埋点和日志不得记录 Token；证券代码等查询参数仅按内部数据管理规则记录。

## 附录 B：术语表

| 术语 | 定义 |
|---|---|
| 数据源插件 | 封装数据源认证、参数组装、上游调用和来源结果的组件 |
| 适配器 | 将某个插件接口的来源数据转换为目标表结构的组件或配置 |
| 下载包络 | 插件向核心流程返回的统一结果结构，来源 `fields` 和 `data` 保持来源语义 |
| 数据集 | 某一数据源接口已经持久化的数据集合，对应一张来源独立表 |
| 来源独立表 | 由 `plugin_id + api_name` 唯一确定的数据库表 |
| 业务唯一键 | 在某个来源接口内稳定标识一条业务记录的字段组合 |
| 空数据 | 上游请求成功但返回 0 条业务记录，不属于失败 |
