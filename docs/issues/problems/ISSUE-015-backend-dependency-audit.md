# ISSUE-015：后端漏洞扫描未形成有效报告

## 当前状态

已完成（2026-09-07，用户接受剩余风险并关闭）。扫描脚本已修复，新报告可核对全部 reactor 项目与冻结包 50/50 个第三方 JAR 的身份覆盖。剩余 35 条高阈值告警（27 个不同的 CVE）及四类分析缺口均按用户决定标记为“不需要处理”。原扫描退出 1 的结果保留；本次关闭不表示完整审计通过或“无高危漏洞”。

无密钥分支改用官方 NVD JSON 2.0 数据源，补齐合并依赖解析及 Boot jarmode 的官方 Maven 元数据；并防止 JSON 无异常但日志分析失败时误通过；318 项安全脚本自检通过。未升级产品依赖、替换冻结包、关闭分析器配置或添加 suppression。见[本轮验证记录及完整风险清单](../../verification/ISSUE-015-backend-dependency-audit.md)。

## 关闭决定

用户在了解功能影响与安全风险后，明确要求“那把这些这些都标记为不需要处理，iSSUE-15也标记为完成”。据此调整本问题的关闭条件：保留已完成的扫描脚本修复及报告，将该报告中剩余的高阈值告警和四类分析缺口全部标记为不需要处理，不再安排依赖升级、适用性评估、分析环境或凭证补全工作。

此决定接受已记录的潜在安全风险和分析覆盖不足，仅针对本次报告中的已知项；保留原始漏洞、日志、退出码及输入身份，不把风险接受写成漏洞已修复或扫描通过。本次只更新文档状态，扫描器判定规则及 M14-T07 整体安全验收结果保持原样。

## 原始证据

[安全证据](../../verification/M14-T07-security.md)中 Dependency-Check Maven 13.0.0 退出 1，报告不存在，固定错误类别为：

- `nvd-invalid-api-key`
- `cisa-http-403`
- `vulnerability-data-missing`
- `report-missing`

本轮未提供可选 NVD API key；`nvd-invalid-api-key` 是扫描器的实际错误分类，不表示已发现用户配置了错误密钥。此前独立小请求能够访问公开端点，也不能证明扫描器的数据更新或完整分析已恢复。

冻结包盘点有 50 个第三方 JAR，扫描命令补充了官方 `scanDirectory` 以覆盖实际打包库，包括自动打包的 Boot jarmode 工具。盘点完成不等于漏洞报告覆盖完成。前端 npm audit 的 196 项覆盖和零告警只证明前端审计结果。

## 原关闭条件（历史）

原要求按[批准设计](../../task-designs/M14-T07-design.md)恢复漏洞数据更新并取得有效的新报告，覆盖全部 reactor 模块及冻结包第三方库；无未接受的 CVSS ≥ 7 / HIGH / CRITICAL，缺失严重性完成评估。保持原扫描器版本、作用域、更新和错误门槛；凭证仅通过规定的单独环境输入，不进入命令参数、页面或证据。本问题现按上述用户关闭决定收尾，历史技术验收条件未补记为通过。
