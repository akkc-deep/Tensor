# ISSUE-012：查询接口未拒绝任意字段参数

## 当前状态

已解决（2026-09-07）。查询入口按已声明参数名做白名单校验，额外参数返回 400 / `PARAM_INVALID`。新冻结生产包 S06 六项全部通过，合法查询、业务表指纹与上游调用次数保持预期。完整证据见[验收记录](../../verification/ISSUE-012-query-extra-parameters.md)。

## 实际证据

对 `/api/v1/data-sources/tushare_pro/datasets/stock_company/records` 分别附加以下参数，[安全证据](../../verification/M14-T07-security.md) S06 六次均为 HTTP 200：

| 参数 | 固定测试值 |
| --- | --- |
| table | other_table |
| column | introduction |
| columns | * |
| sort | ts_code DESC |
| orderBy | ts_code |
| sql | SELECT 1 |

每次业务行及 stub 调用数均未变化。证据证明“未拒绝输入”，不证明提交的 SQL 被执行。

## 关闭条件

[批准设计](../../task-designs/M14-T07-design.md) S06 明确要求全部返回 400 / `PARAM_INVALID`，忽略参数后返回 200 也不满足要求。按问题流程确认输入边界的修复设计，保留固定 SQL 标识符和值绑定、安全错误、合法查询行为，并以新冻结生产包取得六项通过证据。

## 修复设计与实施计划

本轮按用户“解决 ISSUE-12”的要求恢复已有 S06 合同。根因是 Controller 只绑定具名 `@RequestParam`，Spring 默认忽略未绑定的参数，现有校验无法看到额外参数名。

查询入口读取完整参数映射，按接口已声明的七个参数名做白名单校验：`tsCode`、`tradeDateFrom`、`tradeDateTo`、`annDateFrom`、`annDateTo`、`page`、`pageSize`。出现其他名称即抛出现有 `InvalidQueryException`，由全局 advice 返回 400 / `PARAM_INVALID`，不回显输入。参数名区分大小写，空值与重复的未知参数同样拒绝。沿用现有类型绑定、数据集筛选权限、分页、固定 SQL 标识符和值绑定。

1. 回归：实际 Controller、全局 advice、请求 ID 和安全头过滤器共同装配，覆盖六类 S06 参数、未知名称、错拼名称、空值和重复参数；确认修复前返回 200，修复后安全错误且数据库零访问。
2. 修复：增加参数名白名单校验，运行查询入口、SQL 构建和 Web 错误处理回归，验证合法筛选、分页和精度行为。
3. 验收：独立源码快照构建生产包，固定源码及 JAR 身份，复用 M14-T07 的合成下载/查询前置步骤和 S06 检查，逐次核对业务表指纹与 stub 调用数。参数错误的完成事件归属 ISSUE-013，不在本轮改变。

## 完成结果

- 新增 10 组参数化回归修复前均因 200 而失败；修复后每组单值与重复值共 20 个请求均返回安全错误且数据库零访问。
- 定向 111 项测试通过，覆盖查询入口、真实数据库查询、SQL 构建、全局错误处理和 Web 配置。
- 独立快照完整构建通过：397 项后端单测、4 项生产包合同、170 项前端单测。
- 新生产包 S06 6/6 及合法查询复核通过；限定范围共 20 项门禁、311 项检查器自检通过。安全扫描、身份复核与自有资源清理通过。ISSUE-013 的参数错误完成事件仍单独处理。
