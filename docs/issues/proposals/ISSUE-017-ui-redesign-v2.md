# ISSUE-017：数据优先的研究工作台 UI 提案

方案状态：第二版初步提案，待视觉评审，尚未确认为实施依据。

用户补充要求：字体、UI 动效、表格对齐与单元格大小也需重新设计。布局、字体、动效和表格排版同为本轮核心交付，不能只做颜色、圆角或字号微调。

关联问题：[前端 UI 第二版](../problems/ISSUE-017-ui-redesign-v2.md)。上一轮[最终方案](ISSUE-004-ui-visual-concepts.md)与验收记录保留；本提案提出新的布局方向，不覆盖历史文件。

## 目标与方向

沿用当前产品定位：用户选择证券数据接口、填写参数完成下载，再筛选和核验已入库的数据。页面属于操作工具，设计应让数据、输入和反馈成为视觉中心。

建议采用“数据优先的研究工作台”：用准确的网格、清晰的文字层级、低饱和浅色表面和紧凑的数据排版形成专业感。Tensor 品牌标识保留在导航中，主色集中强调当前入口、焦点和主要动作。

| 候选方向 | 收益 | 代价与判断 |
| --- | --- | --- |
| 数据优先的研究工作台（推荐） | 重组配置与结果的关系，表格更早出现，浅色界面适合现有长表和表单 | 需要调整页面结构及视觉验收基线 |
| 深色金融终端 | 视觉差异大，高密度数据具有鲜明气质 | 需要完整深色主题、弹层和状态配色；当前功能也没有终端式行情分析，不建议本轮采用 |
| 保持现有结构，微调颜色与圆角 | 改动少 | 难以解决标题重复、配置区过高和结果面板空的问题 |

## 页面结构

### 公共框架

- 桌面侧栏建议约 184px，保留 Tensor、数据下载、数据查看；设置放在底部，移除无交互含义的导航编号及宣传性页脚。
- 工作区使用一个紧凑页头，直接显示页面名称和一句必要说明；合并当前工作空间栏与大标题区，移除右侧装饰线条。
- 查看页使用全部可用宽度；下载内容建议最大宽度 960px，设置内容最大宽度 800px，均与工作区标题左对齐。
- 680px 以下使用紧凑品牌栏及三个带文字的导航入口；页头、导航、表单不重复说明当前页面。

### 数据下载：连续配置与结果回执

```text
数据下载
┌ 数据源 [Tushare Pro ▾]     数据接口 [日线行情 · daily ▾] ┐
│ 行情与估值 · 交易日                         接口详情 ▾ │
│ 请求参数                                               │
│ 交易日期 [按元数据呈现]                                 │
│ [开始下载]                                              │
├ 本次结果                                               ┤
│ ✓ 下载成功       上游返回 12    插入 10    更新 2         │
└────────────────────────────────────────────────────────┘
```

此图仅表达布局；12 / 10 / 2 沿用旧验收的样例计数，不代表本轮执行了下载。

- 用一个连续任务区替代常驻的左右大面板。先选择接口，再填写参数并提交，结果紧接操作区显示；反馈区域按内容自然增高。
- 接口中文名称和技术标识在选择结果中展示；分类、查询方式采用紧凑摘要。完整说明保留在可通过键盘展开的“接口详情”中，不删除元数据内容。
- 参数沿用元数据顺序，桌面可排两列，窄屏单列；必填标记、格式提示、字段错误就近呈现。无参数接口直接呈现提交动作。
- 待操作时显示一行引导；加载时在按钮与结果区域显示真实请求状态；成功时展示状态与三项计数；空结果明确为 0 条；失败时完整展示原因、请求 ID 及符合条件的原参数重试入口。
- 每次有效提交仍对应现有业务请求。反馈从加载切换为结果时不重置表单、不抢夺键盘焦点；窄屏长错误允许正常向下延伸。

### 数据查看：筛选工具条与数据表共用一个工作区

```text
数据查看
数据源 [Tushare Pro ▾]   数据集 [日线行情 · daily ▾]
证券代码 [          ]   交易日期 [开始]—[结束]  [查询] 重置
────────────────────────────────────────────────────────
日线行情 · daily                         共 201 条（示例）
证券代码 │ 交易日 │ 开盘价 │ 最高价 │ 最低价 │ 收盘价 │ …
… 数据行；固定证券代码列，宽表内部滚动 …
────────────────────────────────────────────────────────
共 201 条（示例）                       每页 50 条  ‹ 1 ›
```

- 数据源与数据集是第一排上下文，筛选项与查询动作紧随其后；移除独立“查询配置”大卡片和重复的结果卡片套层。
- 所有可用筛选项仍可见，按元数据顺序自动换行；不为了达到首屏指标截断复杂表单。查询、重置高度和基线统一。
- 表格上方保留数据集名称及已有响应提供的记录数。中文字段名称优先阅读，必要的技术标识作为次级文字；单位、原列序和全部来源列保留。
- 表格正文建议 14px、行高约 40px，数字按下节规则对齐并使用等宽数字；保持精确字符串、正负号及原涨跌语义，不随主题色改变涨跌含义。
- 减弱非必要的网格线，通过表头底色、水平分隔、行悬停和固定列边界帮助定位。保留长文本完整查看及键盘横向滚动。
- 分页与表格成为同一块内容，默认 50 条及 20 / 50 / 100 选项保持不变。无数据、加载、失败反馈占据结果区，筛选上下文仍可辨认。

### 表格排版：按内容分配尺寸，建立统一对齐规则

当前大部分列的最小宽度为 140px。第二版使用列级规则决定整列宽度，同一列的表头与所有数据行共用宽度；不让每个单元格自行撑开，也不把全部列拉成等宽。以下是试排起点，最终宽度需容纳实际字体、表头和格式化内容。

| 内容类型 | 建议起始列宽（含左右留白） | 对齐规则 |
| --- | --- | --- |
| 证券代码、短标识 | 120px | 表头与内容左对齐，单行；证券代码保留固定列 |
| 日期 | 128px | 表头与日期左对齐，等宽数字，完整显示 `YYYY-MM-DD` |
| 入库时间 | 192px | 左对齐，完整容纳既有时间格式；实际格式更长时扩宽 |
| LONG 整数、数量 | 120px | 表头及数值块右对齐，完整显示大整数 |
| DECIMAL 价格、金额、涨跌 | 128px | 数值块右对齐，列内按小数点对齐；宽度按真实精度扩展 |
| 名称、分类等普通文本 | 160px，可适度分配剩余宽度 | 表头与内容左对齐，单行，完整内容可访问 |
| 长文本 | 280px 起，常规上限建议 360px | 左对齐，单行省略；悬停、键盘及窄屏触控均可查看全文 |

- **表头与正文**：统一垂直居中和左右 12px 留白。表头默认 56px，中文名称与技术标识使用固定两行槽位，第一行基线一致；无中文标签的字段只显示原标识，不重复填充假标题。过长标题统一增加整条表头高度或提供完整查看，不能个别列挤压正文。
- **行高与节奏**：桌面常规数据行 40px，14px 文字配 20px 行盒及上下各 10px 留白；窄屏行高至少 44px。常规文本不任意换行拖高某一行，数字与日期不换行。字体放大时允许整行增长，不硬裁文字。
- **数字与小数点**：保留原始字符串、正负号、末尾零、负零及不同精度；用显示层的整／小数部分对齐和留白校准小数点，不添加可见的零，不四舍五入，不转为 JavaScript `Number`。空值沿用原占位语义并占用相同对齐区域，不能伪装成 0。
- **宽度分配**：按字段角色给出起始宽度，再容纳表头和当前页实际格式化内容。数值与日期的完整显示优先于起始宽度；高精度值需要时扩宽整列。可读宽度总和超过容器时内部横向滚动，不压缩到所有列勉强挤入首屏。
- **翻页稳定性**：同一数据集浏览期间保留已确定的列宽；新页内容更长时仅扩展必要列，不因短内容缩窄。切换数据集才重新计算，避免鼠标位置和视觉锚点反复变化。尺寸计算集中在表格显示层，不给每个单元格增加独立监听。
- **固定列与滚动**：固定证券代码列和正文使用相同行高、边框与悬停底色；横向滚动时表头、表体同步。固定列边缘用一条清楚的分界提示遮挡关系，不能出现文字重叠或双层错位。

验收样例同时包含短代码、日期、空值、负数、不同小数位、19 位整数、38 位精度小数、长中文名称和长字段名。覆盖 daily 与宽财务表；不只用每列内容长度相近的合成样例证明尺寸合理。

### 设置：紧凑设置行与局部样张

- “外观与主题”使用简洁设置区，主题色、HEX、“应用”保持一组；实际应用色与保存状态就近显示。
- 下方用一小块静态界面样张展示表面、按钮、选中项和数据行，随同一套主题变量更新；样张明确标注“外观预览”，不请求业务数据。
- 恢复默认作为次级操作独立放置。保留整页实时联动、刷新恢复、非法 HEX、过亮颜色修正及“仅本次预览”行为。
- 已有主题偏好继续读取，不因改版自动清空；默认主题命名和新默认配色在视觉评审时一并确认。

| 维度 | 建议 |

| 间距 | 使用 4 / 8 / 12 / 16 / 24 / 32px 级差；区块内紧凑，区块间有清晰留白；相邻控件标签、输入和按钮基线一致 |
| 形状 | 面板约 8px 圆角、控件约 6px；阴影用于浮层层次，普通内容主要由底色与间距区分 |
| 尺寸 | 桌面常规控件统一约 40px，窄屏点击目标至少 44px；不会只放大主按钮 |
| 动效 | 导航、控件、弹层和结果回执使用统一节奏；提交到结果的衔接作为重点设计，具体见下节动效方案 |

主题仍联动背景、导航、面板、文字、边界和操作色。新增层级复用现有 `--tensor-*` 与 Element Plus 映射，扩展最少必要变量；正文对比度至少 4.5:1，主操作保持已有 5.5:1 目标，辨识控件所必需的边界与焦点至少 3:1。成功、错误及涨跌保持明确文字或符号，不能仅依赖颜色。

## 字体方案：先看实际字样，再固定排版规则

建议优先试排 **MiSans** 作为统一的中英文 UI 主字体，采用真实的 Regular / Medium / Semibold 字重。此为候选建议，尚未引入字体资产，也未完成许可与实际渲染核验。技术标识使用现有系统等宽字体，控制字体家族数量。

| 文字角色 | 建议规格 | 处理原则 |
| --- | --- | --- |
| 页标题 | 桌面 26px / 600，窄屏 24px / 600，行高 1.3 | 中文不使用当前偏紧的负字距；品牌英文单独校准 |
| 区块标题 | 16px / 600，行高 1.5 | 与正文靠字重和间距区分，减少重复标题 |
| 导航、按钮、字段标签 | 14px / 500，行高 1.4–1.5 | 三页一致，避免同一角色有 550、600、650 等零散字重 |
| 说明正文 | 16px / 400，行高 1.6 | 长说明控制行宽；高密度表单中的短提示可为 14px |
| 表格内容、输入值 | 14px / 400，行高 1.5 | 数字启用等宽数字特性，数值右对齐；验证候选字体是否实际支持 |
| 辅助说明、技术标识 | 13px / 400，代码可为 12px | 不再用 11px 作为表头技术标识的默认尺寸，不通过过浅颜色弱化到难以阅读 |
| 下载结果计数 | 24px / 500，行高 1.3 | 同一字体与稳定数字宽度，不用字距挤压大数 |

试排样张必须包含“数据下载／交易日期／上游返回数”、`Tushare Pro · daily`、`000001.SZ`、`2026-09-09`、`123.4500`、`-0.0000` 和 `9223372036854775807`，同时放在导航、表单、表格及结果回执中比较。保留精确数字及原有单位；辅助文字也要清楚，不能只看放大的标题效果。

实施前确认字体的官方来源、Web 使用与再分发许可，随字体归档必要许可文件。优先本地 WOFF2、只加载实际需要的字重，采用可立即显示文字的加载策略和接近的系统回退；不依赖第三方字体 CDN。中文元数据是动态内容，不能只为演示文案裁剪字形。检查中文标点、中英基线、缺字回退、字体加载前后布局及 200% 缩放。

## 动效方案：围绕一次操作的因果关系设计

重点是“提交 → 等待 → 结果回执”：按钮立即确认提交，等待状态明确，再在同一个结果区域交接给成功、空结果或失败。导航和弹层使用同一组节奏，避免各组件各自弹跳或整页逐块入场。

| 场景 | 建议行为 | 时序与约束 |
| --- | --- | --- |
| 页面切换 | 侧栏保留稳定位置，选中标记与内容短暂淡入同步；不整页滑移 | 约 160ms，可中断；缓存页面不重播加载流程，不增加请求 |
| 按钮和输入 | hover 用背景／边界变化，按下用色阶确认，focus 环立即可见 | 100–140ms；禁用立即生效，不缩放文字、不让按钮上下跳动 |
| 下拉和日期弹层 | 从所属控件附近轻微展开，关闭比打开更快 | 入场约 160ms，退场约 100ms，位移不超过 4px；统一 Element Plus 过渡，避免叠加两套动画 |
| 下载提交 | 提交锁定即时生效，按钮出现加载标识，结果区更新等待说明 | 反馈不等待动画；只表现真实请求在途，不显示虚假百分比 |
| 下载结果 | 等待状态与回执在同一区域短暂交替，成功标记和最终计数一起出现 | 约 180ms；不做数字从 0 递增，返回值立即可读 |
| 查询及分页 | 表格区域保持位置，加载反馈到结果采用轻量淡入；整表一次出现 | 120–160ms；不逐行、逐列播放入场，不延迟翻页 |
| 字段错误与失败 | 就地出现错误与恢复动作，必要的错误焦点按原规则处理 | 约 120ms；不抖动表单，长错误完整可见，状态播报仅一次 |

共同到达曲线建议 `cubic-bezier(0.2, 0.8, 0.2, 1)`，退场用更短时长；颜色反馈用简单缓动。将少量时长和曲线集中管理，避免每个组件独立调参。优先现有 Vue 过渡与 CSS，不新增动画依赖，不使用 `transition: all` 或持续装饰循环。

动画不能决定业务状态何时提交，不把请求、禁用、焦点或结果更新绑在 `transitionend` 上。快速切换路由、连续打开／关闭弹层、请求在设置页期间完成时，最终状态与当前操作一致。结果容器自然布局，避免对表格和大容器持续动画化宽高；减少动画模式去掉位移和非必要过渡，保留静态加载说明、状态文字和即时焦点。

动态预览需可以反复操作上述场景，并对比开启与减少动画模式；附短录屏或等效可复现交互证据。静态截图只验收落定后的排版，不能证明动效好看或流畅。

## 验收方式
