# ISSUE-018 方案草稿：按日期区间批量下载

状态：关键方向已确认，草稿待细化，尚未实施（2026-09-11）。官网逐项依据见 [ISSUE-018](../problems/ISSUE-018-date-range-batch-downloads.md)。

已展开为[详细设计](../../task-designs/ISSUE-018-design.md)，涵盖模块合同、任务与批次表、后台状态机、事务、API、前端及验证命令；详细设计待复核，本文保留关键方向摘要。

## 目标与范围

- 用户选择一个接口、股票或交易所及日期区间，一次操作完成分批下载；继续保留各接口的股票必填规则。
- 31 项原生区间接口使用 `start_date + end_date`；`top_list` 按交易日遍历，`dividend`、`disclosure_date` 按公告日期遍历自然日。
- `pledge_stat`、`stk_rewards` 暂不增加区间能力；4 项无日期输入的接口保持现有方式。接口开放前需确认数据可用性与完整提取方式。
- 日期控件按接口区分交易日期、公告日期、报告期和上网发行日期；不扩展为多股票或多接口同时下载。

## 后台执行与页面查询

- 提交下载时，后端先持久化任务，再立即返回任务 ID；下载由后台执行器处理，与提交请求的生命周期分离。
- 后台持续执行批次、入库并更新数据库状态。页面按任务 ID 查询进度和结果，不通过长时间等待提交请求获取最终结果。
- 刷新或关闭页面不影响已提交任务；再次打开后可从任务记录找到任务，查看进度、结果及失败批次，不依赖原页面内存。
- 服务重启后保留已成功批次；中断任务经确认停止执行后，由用户手动恢复未完成批次，首版不自动恢复执行。

## 分批执行与完整性

- 同一任务内由后台串行请求并控制频率，设置任务执行时间、批次数和累计数据量限制。
- 单次行数上限来自官网，按接口配置。返回条数达到或超过已确认上限时，拆小区间重新请求；父区间结果不直接入库。
- 最小日期片段仍达到上限时，标记失败并说明完整性无法确认。官网未明确上限或只给默认返回条数的接口，先核验补齐方式，不猜上限、不凭返回成功认定完整。
- 拆分后的批次覆盖原区间，保留原股票、交易所和日期语义；批次划分与执行记录均持久化。

## 每批独立入库

- 每批下载、校验及适配成功后立即入库，使用独立事务；证券数据写入与批次标记成功在同一事务中完成。
- 单批失败只回滚该批数据，另行保存失败记录，继续处理其余可执行批次；已有成功批次保留。
- 空数据批次记为成功、0 条。重复下载沿用业务键保证幂等。
- 最终区分全部成功、部分成功、失败；展示成功与失败批次数、已入库条数和失败区间。存在失败、未完成或完整性未确认批次时，不显示全部成功。

## 持久化与手动重试

- 保存任务与批次关联、完整请求参数、日期区间、执行状态、重试次数、失败原因、更新时间及结果计数。
- 批次状态包含待执行、执行中、成功、失败。刷新页面或重启服务后，仍能从数据库查询执行结果及未完成批次。
- 首版提供手动重试：读取失败批次重新执行，跳过已成功批次；服务中断遗留的执行中批次，经确认已停止执行后可恢复处理。手动重试与恢复均交由后台执行器执行，页面继续查询状态。
- 持久化记录用于查询和恢复；失败批次不自动重试，服务重启后不自动续跑中断任务。

## 多数据源复用

- `tensor-core` 统一负责后台批次执行、任务与批次持久化、状态流转、中断恢复、手动重试、分批事务和结果统计；记录通过数据源与接口标识区分归属。
- 插件负责认证与上游请求、参数映射和日期语义，并提供返回上限、分页 / 结束标记、可拆分条件及调用频率规则；数据适配器负责字段转换，数据集定义提供业务键和来源表信息。
- 区间二分、逐日遍历可提供公共实现，由插件声明适用条件；核心层不硬编码 Tushare 的参数名、行数上限、股票规则或交易日历。
- 前端复用数据源选择、动态参数表单、批次结果与重试入口，按插件元数据展示具体参数；新数据源沿用公共执行和入库流程。
- 现有通用插件入口、参数校验、动态表单和入库能力继续复用；批次管理与持久化重试作为本次新增的公共能力。
- 当前参数绑定只支持固定组合，新数据源出现不同参数时仍可能需要扩展绑定；新增批量能力的插件合同待细化，不承诺任意数据源都能仅添加插件完成接入。

## 后续细化与关键验收

- 后续确定表结构、提交及任务查询接口、后台执行器与任务领取规则、插件批量能力合同、批次拆分记录、并发重试保护、任务超时与中断恢复边界，以及具体限流和规模配置。
- 验证提交后立即返回任务 ID；刷新或关闭页面后任务继续执行，再次打开可查询同一任务；服务重启后中断任务可手动恢复，成功批次不重复执行。
- 验证“三批中一批失败”：成功两批已入库，失败区间可查询，手动重试只处理失败批次。
- 验证重启恢复、重复重试幂等、数据与成功状态事务一致，以及达到上限后拆分仍不漏区间；按接口日期语义完成真实下载验证。
- 用非 Tushare 的测试插件验证公共批次执行、入库及重试流程，确保它们不依赖 Tushare 特有参数和规则。
