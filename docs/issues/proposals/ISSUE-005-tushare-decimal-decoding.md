# ISSUE-005：精确保留上游 JSON 小数

## 授权与范围

用户“继续修复”授权独立产品修复。延续 M05-T04 的精度设计，在 `TushareProClient` 私有 mapper 启用 `DeserializationFeature.USE_BIG_DECIMAL_FOR_FLOATS`，让 JSON 小数直接进入 `BigDecimal`。不修改转换器、元数据、数据库、公开错误合同、样例和积分范围，不接受 `Double`、舍入或将错误转成 EMPTY。

其他解析门禁（重复键、尾随数据、标量强制转换、响应大小）、超时、单次请求和日志安全保持原行为。整数、null 和字符串保持现有语义。

## 实施与独立验收任务

1. **精度回归与修复**：在既有客户端测试增加真实客户端读取合成 JSON 的精度测试，覆盖普通小数、超过 double 精度的小数、指数、整数、null。在 app 模块增加客户端到真实 `GenericDatasetAdapter` 的 `stock_company` 合成完整字段测试。先运行两项观察 RED，再加入唯一 mapper 配置并运行 GREEN。
2. **关联验证与产物**：运行客户端/安全校验和通用适配转换测试；在自有临时源码快照构建 production/acceptance JAR，执行既有打包合同。保持工作区原 acceptance JAR SHA `a69874afa6ce783d4ef4e16a678ddb0ff457f2948b68f509a8e4a2c00440bcac` 不变，记录新路径与 SHA；比较归档内容，核对变化符合本修复。
3. **复审与验收接入**：独立代码复审；明确记录 M14-T05 新一轮使用的修复产物/hash，原失败证据保留。只有本地检查成立并完成一次性启动材料准备后，交用户在已有 Token 的终端运行一次。该轮仍为 40 接口/48 样例/9 项固定排除，真实失败仍 BLOCKED，全子集通过才 PAUSED。

## 证据边界

本地测试只使用合成数据，不访问真实上游，不读取用户 Token，不输出或持久化真实行。合成测试能确认解码缺陷修复，不能确认上次真实失败的具体字段，也不能代替真实矩阵。新验证记录在本问题中；原真实证据文档已扫描版本不改写。
